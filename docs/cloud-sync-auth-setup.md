# メール認証・手動同期 導入メモ

この機能は**隔離された検証ブランチ上の試作**です。本番アプリ／公開済みプレビューmainは変更しません。

## すでに実装したこと
- 初期値は端末ローカル保存のみ。本人が同意してから認証・手動同期。
- 登録済みメールだけにログインリンクを送る（アプリから新規登録はしない）。
- DB `allowed_sync_users` に許可登録したユーザーのみ読み書き。
- 端末の既存学習履歴は残し、JSONバックアップを同期前に自動生成。
- 未登録イベントのみ送信し、DBでは更新・削除できない。
- 問題の本文・回答選択肢・名前は送らない。
- 同期をオフにしてもサーバー側既存データは消去されない。

## 人が行う必要がある設定（コードからは実施していない）
1. Supabase Dashboard > Authentication > Users から**本人のメールだけを招待／登録**する。メールやUIDをチャットに貼らない。
2. Dashboard > Authentication > URL Configuration で検証用の**正確なHTTPSプレビューURL**を Site URL と許可リダイレクト先に登録する。URLを推測して設定しない。
3. Dashboard > Table Editor などで `auth.users` の本人UIDを確認し、管理者として `allowed_sync_users` にそのUIDを1件追加。登録がなければ同期は拒否される。
4. メールリンクのログイン動作は**実際のサイトで**確認する。LINE内ブラウザとSafariでセッションは独立する場合がある。

## テスト計画
- ログインなし、未許可、許可本人、別のログイン済み本人で、DB閲覧・追記の境界テスト
- 初期オフ時に通信が発生しないことのネットワーク監査
- 同期直前の確認ダイアログとJSONバックアップ
- 同じ端末で2度同期しても重複登録されない
- iPhone SafariとiPad Safariで同期した場合の履歴一致
- LINE内ブラウザでリンクを開いた場合のログイン・セッション
- エラー/回線切断時に端末の履歴が維持される
- 最終的に自動結合の重複や別端末の日時が合うかを手動検証

## 注意
- バックアップされるJSONは端末に保存されるので、他人に共有しない。
- セキュリティ上、service_role鍵やDBパスワードをクライアントに載せない。公開用publishable keyのみ利用。
- 当面正式版にマージしない。実データの同期は本人の認証確認後に行う。
- 検証ブランチのプレビュー環境が作られるまで動作確認はできない。
